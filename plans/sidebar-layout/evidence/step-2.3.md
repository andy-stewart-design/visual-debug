# Step 2.3 — Persistent website access and direct sidebar Start

- Implementation is present in the bounded source set: WXT declares `http://*/*` and `https://*/*` host access alongside `activeTab`/`scripting`; `site-access.ts` checks the actual grant before sidebar Start; background injection and sidebar-controller paths keep query/reopen passive and report unavailable guidance when access is missing. The grant covers ordinary HTTP(S) tabs only; browser-internal, `file:`, and `ftp:` targets remain unavailable. Protected HTTPS targets may be rejected when explicit Start attempts injection.
- The direct sidebar Start path can inject after the browser has granted site access, while a toolbar start remains available. It does not promise a fresh prompt on every unpacked reload or call `permissions.request`; browser controls, installation/update, and site settings own the grant. Native protected HTTPS pages may still refuse injection and are reported as unavailable/error rather than treated as active.
- Verification passed: focused site-access/controller/browser/state/activation tests (5 files, 101 tests), `pnpm check`, `pnpm test:unit` (13 files, 175 tests), `pnpm build`, `pnpm --filter @visual-debug/extension build:firefox`, and `git diff --check`. Regression cases cover no toolbar click for a granted fresh site, no auto-start, withheld grants, localhost port-free match patterns, delayed permission checks after tab/close changes, preserving a newer active acknowledgement, protected HTTPS refusal, cancellation, and reload reinjection. These are unit/composition/build checks, not native grant proof.
- Inspected production manifests: Chrome MV3 declares `host_permissions: ["http://*/*", "https://*/*"]` plus `activeTab`, `scripting`, and `sidePanel`; Firefox MV2 folds exactly those origins into `permissions` alongside `activeTab`/`scripting`. Neither adds `content_scripts` automatic registration, a popup, `<all_urls>`, or non-HTTP(S) grants. Both production outputs are rebuilt; Firefox's pre-existing metadata warnings remain.
- **Manual/Phase 2 gate pending:** reload both extensions and test tabs in Chrome and Firefox Developer Edition, approving website access through the browser if requested (developer reloads may not prompt). With the sidebar already open, visit a fresh ordinary HTTP/HTTPS site without clicking the toolbar: it should be Stopped with Start available; only Start should inject/activate. Also check reload → direct Start, switching/reopening without activation, denied/withheld access, protected/browser-internal pages, Stop/close cleanup, and window isolation. A site's actual grant is required; missing URL metadata or browser-managed denial must not produce false active state. No native acceptance, stable-Firefox support, AC14 completion, or Phase 2 exit is claimed.
